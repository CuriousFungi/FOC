TROUBLESHOOTING
================================================================================

PROBLEM: Angles still stuck at 0.0 after fix
─────────────────────────────────────────────────────────────────────
POSSIBLE CAUSES:
1. Fix not actually applied (check code)
2. Build didn't include changes (clean rebuild)
3. Old firmware still on board (re-flash)

ACTIONS:
☐ Verify lines ~3530-3540 in StepperMotor.cpp show new code
☐ Clean build and rebuild completely
☐ Re-flash firmware
☐ Power cycle board


PROBLEM: g_encoder_mech_angle_raw now updates but motor still rough
─────────────────────────────────────────────────────────────────────
POSSIBLE CAUSES:
1. Calibration offset wrong
2. Direction inversion incorrect
3. Different issue (not the angle stuck bug)

ACTIONS:
☐ Check g_calibration_offset_elec value
☐ Re-run alignment/calibration
☐ Check g_align_direction_inversion flag
☐ Verify pole_pairs = 50


PROBLEM: Some angles update, others don't
─────────────────────────────────────────────────────────────────────
DIAGNOSIS: Pipeline breaks at a specific stage

FIND THE BREAK POINT:
☐ g_encoder_mech_angle_raw updates? → YES/NO
☐ g_encoder_elec_angle_raw updates? → YES/NO
☐ g_encoder_elec_after_offset updates? → YES/NO
☐ g_cached_encoder_angle updates? → YES/NO

First variable that's stuck = where pipeline breaks


PROBLEM: Motor runs backwards
─────────────────────────────────────────────────────────────────────
CAUSE: Direction inversion flag may be wrong

ACTIONS:
☐ Check m_invert_output flag during alignment
☐ Re-run calibration to determine correct direction
☐ Manually toggle direction if needed
